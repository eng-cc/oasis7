# Core 跨模块变更影响检查清单

审计轮次: 4

## 目的
- 保留 `TASK-CORE-003` 的历史来源，提供可复用的跨模块影响检查提示，覆盖设计/代码/测试/发布四类影响面。
- 当前开发、验证、评审和合入以[开发流程规范](../../engineering/workflow/source-of-truth.md)为准；本清单不新增任务身份、固定角色、审批材料或独立完成台账。

## 适用范围
- 用于跨两个及以上模块的需求、行为或接口变更评审，按实际影响选择检查项；普通文字、索引或历史定位修正不因触及多个目录就要求全套发布验证。
- 发布、迁移或恢复项仅在本次确实涉及相应动作时适用；真实权限、安全、兼容、数据丢失风险与有效暂停继续约束相关动作。

## 输入
- 受影响要求及真实产品/专业条款；已有 PRD-ID 与适用 Trace ID 沿用，不为简单编辑虚构产品要求。
- 受影响模块设计、当前 PR 与真实 CI/评审记录；Issue/Project 按需使用。
- 本次已执行验证的命令、版本、环境、实际结果及未覆盖范围；适用发布工作另核对其发布/恢复合同。

## 使用规则
- 可用 `✔ / ❌ / ⚠ / N/A` 表达通过、失败、待核实与不适用，也可直接在当前 PR/评审中写等价结论，不要求复制整表。
- `N/A` 说明具体不适用理由和范围；存在适用义务但未执行或缺前置时记为 `⚠`/blocked，不以 N/A 代替。需要替代验证时说明其真实证明边界；是否独立评审按 workflow 风险触发，不要求每行另找评审人。
- `❌` 或 `⚠` 说明受影响动作、事实及处置。真实阻断问题须修复或以可核实事实证明不适用；仅登记整改人和日期不能使阻断通过。
- 非阻断建议可说明理由后不改，不自动要求整改期限、临时缓解或复审日期。只有实际接受了需跟踪的风险、例外或后续义务时，才按对应专业合同记录责任、条件和复核时机；不能借本清单豁免必要验证或用户暂停。

## 阻断条件
- 必要验证未成功、真实正确性/安全/数据丢失风险未解决、身份不明或有效暂停时，按 workflow 阻止相关合入或操作。
- 要求/设计/证据缺失导致本次相关结论无法核实时，不得宣称该链路或发布通过；追踪检查不能被历史 TASK/ROUND 标记代签。
- 不适用的发布项、未采用本表或未填写通用期限本身，不构成额外阻断。

## 阻断后的处理与恢复
- 相关发布必要条件不满足时，发布结论保持阻断，不因登记整改、补齐模板或删除标签而恢复。
- 可继续已授权的诊断、代码修复、文档修正和测试，以及不依赖该阻断结果的其他工作；不限制为只能补文档/测试/证据。
- 修复后验证实际变化及受影响范围；必要结果、适用评审和操作授权满足后，才重新判断相关合入或发布。新候选不能继承旧版本未覆盖的通过结论，原失败证据保留。
