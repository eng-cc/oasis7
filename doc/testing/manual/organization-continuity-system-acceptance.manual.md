# 组织连续性与处置系统验收手册

Owner：`qa_engineer`；生命周期：`active`；Last reviewed：2026-10-09。

本手册是[组织连续性与处置设计](../../world-runtime/runtime/organization-continuity-and-disposition.design.md)的目标验收计划，当前未执行，不构成运行或发布证据。实现前由 runtime / game / P2P owner 冻结政策、schema、容量与接口；缺少测试驱动或权威读面时记录未验证，不用文档检查代替。

运行须固定 source/tested tree、政策/快照、环境、输入顺序与注入点；每场景留存前后资产、义务占用/履行、授权范围、请求和 receipt，失败差分及未覆盖范围。局部 fixture 不证明真实网络，表面截图不证明状态原子性。

<a id="oc-verify-001"></a>
### OC-VERIFY-001：处置顺序和独立权利

固定 runtime fixture，包含独立成员资产、未完成合同、托管余额、债权责任、Agent/设施和剩余。分别尝试跳阶段、未知义务、重复返还及提交失败；核对拒绝零资源变动，只有全部前序条件成立才进入下一步，资产总变化与每步唯一 receipt 对账，Agent 身份/历史不删除。覆盖 OC-1/2；不证明真实拍卖价格或外部结算。

<a id="oc-verify-002"></a>
### OC-VERIFY-002：基础阶段与请求层

固定权威时间/政策，覆盖通知事实纠正、未读/不可达、保护前后边界、无效资格、reclaim/申诉登记/拒绝/过期/撤回/确认以及撤销回到保护。逐项检查可做/不可做与基础阶段不被 pending 请求覆盖；已解决新事实创建新程序。覆盖 OC-3/4/6；时长数值从实际政策取，不在测试中另立规则。

<a id="oc-verify-003"></a>
### OC-VERIFY-003：交接与重复效果竞态

构造同范围两次替代、部分重叠、互不重叠、旧授权执行/撤销、reclaim/申诉并发，枚举合法权威提交顺序。注入收缩旧范围、激活新范围、写 receipt 前后的崩溃及响应丢失；核对每次成功交接只有一个 receipt、重叠范围最多一个授权、失败全部不变、不重叠范围保留。旧待决请求不自动迁移；换 ID 新请求须核验同来源已履行/占用，无重复处分。覆盖 OC-7 与 OC-4。

<a id="oc-verify-004"></a>
### OC-VERIFY-004：恢复、真实读面与隔离

同候选 checkpoint + journal 重启和真实多节点回读，比对阶段、授权范围、占用/履行量和 receipt；缺依赖/未知版本必须阻断，不能重放 committed。按实际容量阈值注入超限与超时，核对无关组织不被冻结。正式外部浏览器窄屏/桌面及 Agent/API 对照同一权威结果，检查基础阶段与待决请求并存、原因/义务/下一步可读，陈旧投影不表示已恢复。覆盖 OC-5；本次未提供专用测试、浏览器或跨节点运行证据。
