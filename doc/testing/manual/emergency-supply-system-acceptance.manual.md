# 紧急保供系统验收场景

- Owner role：`qa_engineer`
- 状态：active 验收计划，未执行；不是测试通过或发布证据。
- 配套设计：[紧急保供系统设计](../../world-runtime/runtime/emergency-supply-authorization-and-settlement.design.md#des-wr-es-001)

执行前必须有实现候选、专业政策版本、可检查权威状态与 receipt 的环境；缺任一项保持未验证。记录每个场景的候选提交、配置、输入、前后资源状态、请求 lineage、receipt、实际结果与未覆盖范围。以下场景不要求新增通用流程记录。

<a id="es-verify-001"></a>
### ES-VERIFY-001：授权矩阵

同候选下构造普通价格波动、局部故障、有效危机，以及逐项缺失授权包、未知政策、未开始/到期、越界主体/地点/品类和无效授权来源。分别登记与尝试执行；核对只有完整有效输入能够进入执行，其余库存、余额、资格与需求履行不变，常态交易继续。

<a id="es-verify-002"></a>
### ES-VERIFY-002：冻结、竞争与原子性

固定五类快照及请求集合，枚举等价输入排列和重复投递，比较每主体分配向量与确定回放。若支持 lottery，固定权威 seed 验证相同结果，缺 seed 拒绝。分别漂移资格、需求、范围、资源和政策；注入日志发布失败、响应丢失、两批次争用同资源及同请求身份不同内容。判定失败无部分变更、重复返回原 receipt、资源/资金守恒；关闭后的晚到请求不能改批次，已提交政策更新不能重排。

<a id="es-verify-003"></a>
### ES-VERIFY-003：退出与恢复

覆盖开始前、开始时、到期前、到期时；将提交、撤销、续期和申诉裁决按两种权威顺序测试。登记、冻结、部分分配、在途及待结算均分别恢复；检查剩余资格失效、旧请求不自动迁移、已确认结果保留。在新授权下显式关联并申请剩余量；更换 ID、重复需求或隐藏关联不得第二次获益。增加旧在途未结算与新授权请求并发场景：可申请量扣除旧活跃承诺；旧最终结算只把占用转为已履行；旧终止/释放与最终结算竞争只产生一个合法结果；重复释放、迟到结算与恢复不能腾出同一量供第二次分配。缺需求证明、活跃承诺量或恢复依赖时阻断。已提交响应丢失返回原 receipt；旧授权失效后不得重做未提交效果。

<a id="es-verify-004"></a>
### ES-VERIFY-004：物理边界、读面与隔离

针对采购、补偿、分配、rationing 分别验证适用合同；路线不可达、目的地存储不足、合约未结算时不得显示完成。尝试转让、叠加、兑换资格，核对原子拒绝。正式 Viewer/API/Agent 在同候选读出自己的四类分配结果、独立履行阶段、原因与真实下一步；测试重连、陈旧节点、超容量、评估超时及退出后历史。full-tier 按[测试规范](../prd.md)选取真实网络/浏览器环境，不能用单进程 fixture 代替。所有结果记录候选提交、配置、政策版本、世界窗口与未覆盖范围。
