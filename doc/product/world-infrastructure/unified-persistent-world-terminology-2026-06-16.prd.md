# 统一持久大世界术语产品契约（2026-06-16）

- 父模块 PRD: [`大世界基础设施 PRD`](prd.md)
- 产品模块总入口: [`doc/product/README.md`](../README.md)

## 产品承诺

oasis7 向玩家表达的是同一个统一持久大世界：玩家的行动、Agent、组织、工业和治理都在同一可持续、可审计的世界叙事中发生。这个产品模型不承诺无限容量、正式 public launch、mainnet 价值网络或无准入限制。

## 术语与玩家边界

| 语境 | 产品术语 | 边界 |
| --- | --- | --- |
| 默认玩家/产品世界 | 统一持久大世界 / unified persistent world | 不把环境或候选运行写成不同玩家世界 |
| 玩家入口 | `viewer` / `pure_api` | 进入同一世界叙事的入口，不是世界类型 |
| 研发与验证环境 | local / test / production environment | 说明运行阶段，不改变玩家世界模型 |
| 技术分区和网络 | `world_id`、network tier | 只作为专业技术语义，不上升为玩家可选择的世界品牌 |

历史网络、环境或兼容名称可以为追溯保留，但不得作为当前玩家默认世界、产品阶段或公开 readiness claim。

## Claim 边界

- “统一持久大世界”描述默认产品模型，不等同于任何特定环境、节点拓扑或已完成的线上就绪度。
- 当前公开状态与技术预览边界由根 [`README.md`](../../../README.md) 拥有；产品层不得以术语收敛推导新的上线或容量 claim。
- 任何公开说明应区分产品模型与专业域提供的实现、验证和运行证据。

## 跨域产品验收

- 玩家可读入口将“统一持久大世界”与 local/test/production、network tier 和 `world_id` 分层表达。
- 专业域证据能够分别说明世界模型、实现状态和 readiness，而不会把其中一项误作另一项的结论。
- 公开 claim 不把历史环境、测试网络或兼容名称包装成新的玩家世界或已完成的正式发布。

## 决策背景与非目标

本专题保留“世界模型、玩家入口、环境和技术分区必须分层”的产品决策背景。它不定义 runtime/P2P/QA/运维实现、代码接口、脚本兼容性、测试命令、任务计划或发布处置；这些事项由相应专业域和 GitHub task evidence 承载。
