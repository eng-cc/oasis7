# 区域章程、地点 tenure 与公共融资

## 文档身份

- 所属产品模块：大世界基础设施
- 上位产品 PRD：[prd.md](prd.md)
- 生命周期：`active`
- Owner role：`producer_system_designer`
- 专业域权威：[`doc/game/prd.md`](../../game/prd.md)、[`doc/world-runtime/prd.md`](../../world-runtime/prd.md)、[`doc/p2p/prd.md`](../../p2p/prd.md)

本文定义空间锚定区域如何取得、维持或失去 charter，地点如何作为可续期的经营建设权，以及区域公共服务如何正当地筹资。它不定义地理算法、投票或 OC 公式、bond 数值、费用/补偿计算、runtime 状态机、界面或宪制修订程序。

## 1. 产品目标

区域不是任意圈地、组织标签或全局主权。它是一个由可审计物理边界、设施和物流关系、实际服务能力与共同维护责任支撑的局部世界 charter。成立后的区域可以协调本地公共能力和竞争/许可等受限事项，却不能任意阻断通行、吞没新玩家的独立路线，或取得超出 charter 的全局权力。

地点保留公共世界与通行属性；玩家或组织取得的是规则化的经营/建设 tenure，而不是可永续主权化的土地。公共融资优先由实际受益者承担，只有真正不可排他的公共品才可采用有界、可复核的共同 levy。

## 2. 区域 charter 生命周期

### 2.1 提案与成立

- 任何玩家或组织均可提案成立、合并或调整区域，但提案必须提供持续设施/物流/服务能力、可验证的本地需求或交付、相应 Agent 与资源能力、边界理由，以及可因虚假、放弃或违约而处理的 bond 证据。
- 区域边界必须空间锚定并可审计；边界、关键设施、物流联系与受影响范围不得只由提案人自报或由短时资本持有推断。
- 审查以本地运营者和受影响服务关系为主，邻近区域保有对边界、外部性和通行影响提出异议的机会；全局层只复核宪制底线、反圈地和跨区域权利，不替代地方对日常经营的判断。

### 2.2 成熟区域的有限治理

- 成熟区域的日常 charter 事项由本地合格主体共同决定：一侧是锁定 OC、可撤回委托和实际控制人封顶所形成的治理资格，另一侧是持续运营、维护或交付贡献所形成的本地贡献资格。两侧都不能单独把资本、短时到访或历史头衔变成无限地方控制权。
- 区域权力仅覆盖 charter 已声明的本地公共项目、服务、许可和受限竞争事项；其不产生任意排他、跨区域军政控制、全局宪制解释权或对未参与者的常态支配。
- 通行和基本独立恢复路线保持可用。容量稀缺时可采用透明、可审计的容量结算或替代/重建路径，但不得以 charter 身份任意拒绝、驱逐或封锁玩家。

### 2.3 退化、恢复与解散

- 当区域持续失去服务、维护、能力、正当性或 charter 条件时，状态应依次进入观察与恢复、暂停高影响权限，再在无法恢复时解散并回归未成熟区域；不得用一次短时失败自动抹去合法区域历史。
- 暂停或解散时，适用的 bond 可按已公开规则处理；设施、Agent、地点 tenure、个人/组织身份和历史 receipt 仍保留其可审计身份，并按规则进入迁移、回收、重建或后续权利处理，不能被静默没收或删除。
- 退化过程必须说明触发事实、当前限制、恢复条件、异议/申诉和下一次可决策点；不能把技术停机、未审计处罚或运维便利伪装成区域 charter 的有效解除。

## 3. 地点 tenure 与公共通行

- 玩家或组织可以取得可审计、按规则转让且依维护和实际使用续期的地点经营/建设 tenure。tenure 支持建设、服务、转让和可读的长期规划，但不把地点转换为永久主权领地。
- 世界和区域保留土地、公共通行与基础权利的公共属性。tenure 只能在到期、长期闲置、明确违约或已预定义的公共必要性下收回；每种收回应具通知、理由、申诉和适用的迁移、可回收拆除或规则化补偿路径。
- 地点、设施或 charter 不得成为任意驱逐、囤地、封锁路线或抹去既有资产/身份的工具。竞争、区域退化或公共必要性也不自动取消未受规则化处理的资产、身份和历史。

## 4. 公共服务融资

- 可排他的设施和服务以透明的使用费、服务费、维护费或自愿合约为主要资金来源；付费人必须能读到收益对象、用途、成本、服务范围和退出或替代路径。
- 只有明确不可排他、跨受益范围的公共品才可采用区域 levy。该 levy 必须由 charter 预先授权，并受目的绑定、受益范围、预算或费率封顶、期限、公开账目和定期复核约束。
- levy 不得成为一般性财富征收、隐蔽补贴、加入组织/选择专业化/维持独立路线的默认前置，也不得绕过宪制紧急保供或普通市场规则。无效、过期、越界或未经审计的征费不得产生有效世界效果。

## 5. 范围与权威边界

产品层定义 `能力与边界证据 -> 本地/邻区/全局分层审查 -> charter 成立或受限 -> 地点 tenure 与服务/融资 -> 退化、恢复或解散 -> 资产、身份和权利的可审计延续` 的制度与玩家结果语义。

`game` 拥有区域服务、竞争、经济平衡和玩家动作；`world-runtime` 拥有空间、资格、投票、bond、tenure、费用、receipt 与恢复的确定性执行；`p2p` 拥有身份、治理/签名与分布式状态边界；QA 拥有具体验证。产品层不决定宪制修订程序，也不将本专题表述为当前已实现、已发布或已获得外部合规结论。

## 6. 组合验收

- AC-1：区域成立/调整样例可核验空间锚定边界、持续能力、需求/交付、Agent/资源、边界理由和 bond；本地审查、邻区异议与全局宪制/反圈地复核的作用范围可区分。
- AC-2：成熟区域样例证明锁定 OC/委托/实际控制人封顶与持续贡献资格共同约束本地决策；区域权力不外溢为任意排他或全局控制。
- AC-3：区域退化样例依次表达观察/恢复、暂停高影响权限和解散/回归未成熟区域；bond、设施、Agent、tenure、身份与历史的处理有 receipt、恢复或申诉路径。
- AC-4：地点 tenure 样例说明取得、续期、规则化转让、收回触发、通知、申诉及迁移/回收/补偿；不能以区域或竞争状态静默没收资产或封锁通行。
- AC-5：可排他服务的使用/维护费与不可排他公共品的 levy 在受益范围、用途、上限、期限、公开账目和复核上可区分；后者不构成常态广泛税收或独立成长门槛。

- 不规定边界测量、资格阈值、锁定 OC/委托权重、贡献公式、bond 金额、费率/预算封顶、tenure 时长或补偿数值。
- 不定义投票、签名、账户聚合、土地登记、设施迁移、费用结算、罚没或申诉的 runtime/P2P 实现。
- 不改变战争、市场、配方、区域竞争或公共紧急保供的专业玩法/经济规则。
- 不决定宪制条款或其修订程序，也不实现任何地图、区域管理、费用或申诉界面。
