# Package source and archive security

Package workflows resolve source identity once in `scripts/package-source-plan.py` from the workflow revision. Release and Mainnet accept the existing semver or daily tag families, peel annotated tags, and require the commit to belong to the default branch history. Testnet accepts explicit branch/tag refs or full commit OIDs and rejects ambiguous bare names. Candidate jobs check out the plan commit without persisted credentials and verify HEAD before executing source. Native artifacts include a platform `SOURCEPLAN.json`; BUILDINFO and bundle manifests report the same checked-out commit. Publishing compares the current release tag against the planned commit without moving it.

All workflow actions use immutable official repository commits with their existing major version comments. Candidate packaging and ordinary Rust jobs have scoped read-only cache tokens and disable normal Rust cache saves. The scheduled full regression and authorized Release jobs maintain caches in the `trusted-v2` generation. Linux packaging keeps its shared toolchain, target and profile identity; Release saves the shared default-branch cache only when the main dispatch checkout equals the event commit. Ordinary native Linux consumers and the existing full-regression writer share the root workspace dev/test cache key and explicit toolchain/WASM environment hash fields. Packaging keeps its independent target/profile boundaries. No restore key reaches an older generation.

The existing workflow governance job runs `.github/actions/cache-permission-probe`, which attempts to reserve a unique empty cache entry with its read-only scoped token and requires denial. It never uploads data or logs bearer tokens or signed URLs. The existing main full-regression job saves a small new-generation sentinel. Candidate governance restores and verifies it when seeded; an initial unseeded result is explicit. Hosted execution is needed to establish token enforcement and the first writer/read restoration sequence. Restore, build and save times remain available in the existing action logs; the first generation switch incurs a separate cold-cache cost.

`scripts/safe_git_archive.py` supplies a bounded archive policy to current operator extraction, checkpoint validation and external WASM summary imports. It bounds compressed input, disk-spooled decompression, physical headers, extended metadata, member count, individual and total file bytes, and elapsed time before `tarfile` interprets PAX or GNU metadata. XZ is rejected because current consumers use plain or gzip tar and an XZ dictionary would require a separate decoder memory policy. Authority extraction rejects links and special files; the optional Cargo snapshot policy preserves safe relative final symlinks. Validation and extraction failures remove the created tree, and Git capture returns a tree only inside its temporary context. The defaults are 512 MiB archive input, 100,000 physical members, 128 MiB per member, 1 GiB expanded file bytes, 4 MiB extended metadata, and 120 seconds. Tests use smaller budgets for boundaries; these values are local policy and cannot be raised by archive content.

The older `scripts/pm` Cargo snapshot consumers, receipt closures and nested dependency-line lock regex from the October 8 proposal no longer exist in the current baseline. The current repository does not restore these deleted governance tools. The remaining remote rollout helper closure carries the new archive policy file with the same mode and checksum validation as the operator extractor. External archive imports load the helper from the trusted script file path under Python isolated mode.

Local regressions cover source resolution, input control characters, ambiguous refs, annotated tags, all current workflow pins and SHA consumers, cache generation, archive traversal and links, extended-header budgets, decompression budgets, executable modes, truncated input, and extraction cleanup. Actual hosted cache permissions, publication tag drift, and platform package execution remain subject to ordinary GitHub workflow validation.
