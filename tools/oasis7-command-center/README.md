# Oasis7 Command Center

macOS desktop implementation of [PR #4518](https://github.com/eng-cc/oasis7/pull/4518), following the [product contract](../../doc/engineering/command-center/command-center.prd.md) and [system design](../../doc/engineering/command-center/command-center.design.md).

This application provides implementation foundations: local document/Git reading, Chinese search, durable decisions and reading history, manual work-to-goal associations, and an optional read-only GitHub PR/check window in four Chinese views. The optional Codex execution connector is experimental and separately enabled for each project/local environment. It manages only its own stdio process and explicitly created sessions; existing Codex work remains in its original tool. Missing runtime observation is displayed as unknown, never as an empty task inventory.

The product revision of 2026-10-13 defines the complete foundation release around daily work: understand priorities and changes, enter the correct existing tool or owned session, handle a real request, and inspect the outcome. A dedicated home summary, unified work detail, external-session navigation, relationship reuse/repair, and three end-to-end user tasks remain implementation or acceptance gaps. Existing views and tests do not establish that complete release. See [the implementation gap](../../doc/engineering/command-center/command-center.design.md#1104-日常工作闭环的实现差距) and [product acceptance](../../doc/engineering/command-center/command-center.prd.md#cc-product-acceptance).

## Project status and architecture

Start with the [project status](../../doc/engineering/command-center/README.md) for long-term direction, current goals, verified progress, recent changes and human attention. Use the [architecture index](../../doc/engineering/command-center/architecture/README.md) to find deployment, authority, persistence, access and recovery boundaries. The [continuous maintenance workflow](../../doc/engineering/command-center/command-center.manual.md) explains who refreshes these documents and when.

These are derived repository documents with explicit source and observation windows. A fresh file read does not refresh the deployment or acceptance facts inside it. Once the documents are tracked in the selected worktree and within index coverage, the direction view lists their indexed chapters under 项目判断来源. Select a chapter to open the existing source detail with its content revision, committed baseline and unchanged verification text; Chinese title/path search remains available. Missing summaries are shown independently, so an unavailable architecture index does not hide the project status. Repository links remain usable when a document is outside the local index. Refresh reads existing content; it does not rewrite summaries, schedule background jobs, start a model or inspect deployed machines.

These direct chapter entry points implement the source-reading fallback in DES-CC-013. They do not provide the four-region actionable projection, automatic freshness/conflict comparison or complete home acceptance. External work should be connected through supported observation or a verified original-tool reference, with read, open and control capabilities shown separately; automatic takeover is outside the contract.

## Run and package

Use the repository Rust toolchain, Node 22 or newer, and the macOS developer tools. From this directory:

```sh
npm --prefix ui ci
npm --prefix ui run desktop:dev
npm --prefix ui run desktop:build
```

The build produces a `.app` under `<Cargo target directory>/<target-triple>/release/bundle/macos/`; use the actual path printed by Tauri. App and bundled CLI use the same explicit target (`--target` or `-t`, defaulting to the host); universal/custom targets and runner target overrides are rejected before building. Its frontend is embedded; launching it does not require Node, Vite, a terminal backend, or the game stack. This is a local ad-hoc signed development build. Developer ID signing, notarization, public distribution, other CPU architectures and older macOS versions require separate verification. The configured deployment target is not evidence of validation on that system.

Choose a Git worktree with the native picker or enter its absolute path. The first load validates the actual repository/worktree and reads its tracked Markdown, HEAD, branch, dirty changes and worktree inventory. Refresh only reads; it never fetches, changes branches, commits or launches a model. Close the window to retain the menu bar entry; use its open action to return and its quit action to exit.

## Sources and personal data

Current-stage sections come from `doc/core/prd.md`'s current delivery/P0 heading. Other goals and rules retain their source path, content version and committed baseline. Document identity does not establish implementation acceptance. The UI does not synthesize a completion percentage or turn long-term goals into current blockers.

The bounded local index covers at most 3,000 tracked paths, 1 MiB per file and 16 MiB in total. It excludes untracked files and escaped symlinks and reports partial coverage. Short Chinese queries use parameterized literal substring search; longer queries use SQLite FTS5 trigram. Document content is rendered as escaped text, with no raw HTML or remote media execution.

SQLite lives in the platform application-data directory (`com.oasis7.command-center`), outside the repository. Personal decisions, confirmed-but-unwritten decisions, work associations and reading versions are scoped to the project/worktree and survive source-cache rebuilding. Unsaved decision edits, association inputs and search text are scoped to the project/worktree for the current App session. Switching to another project clears its visible input context; returning restores that project’s session inputs. Refreshing the same project preserves edits. Switching projects does not save or submit inputs. Restarting does not restore unsaved decision or association inputs; search text continues to follow the existing saved reading preferences. Saving a decision does not update the source document or prove implementation synchronization. Saved reading versions can be opened after the current content changes. Indexing rechecks HEAD, the tracked candidate list, dirty paths and bounded content digests before publication. A detected concurrent change leaves the previous source facts visible with a refresh error; retry after edits settle. This bounded recheck does not lock the worktree or provide an immutable committed-tree snapshot. The runtime database may contain private derived session/request data. Do not copy the entire application-data directory as a public or configuration-only backup; do not remove the database to rebuild the source index. Future schema versions are rejected without clearing data.

Document identity blocks can declare lifecycle and successor information. Lifecycle details retain the original status text and separately show a normalized document category (proposed/draft/active/superseded/retired, other declared values, or unknown for an absent status; invalid/conflicting declarations carry a diagnostic without a guessed category). Notes and code delimiters remain visible; classification uses only the first complete token or leading code span. Older cached reading versions without this projection retain their original display until the source is reread. The client displays these as source facts, with their document revision and committed basis; an `active` declaration does not establish implementation acceptance. Explicit successor references are matched against the currently indexed repository documents and exact section identities. Missing, ambiguous, unsafe or incomplete declarations remain visible and do not enable a guessed jump. Saved historical text stays at its original version; any current successor declaration is labeled separately. The client does not infer authority from modification time, heading similarity or model memory, and does not rewrite formal documents.

GitHub is explicitly connected from the execution view. The app uses an existing `gh` login, checking common absolute installation locations; a different absolute executable path can be selected. It currently supports `github.com` and reads a bounded window of the latest 100 PRs, including the returned check summaries. This window is partial, not a whole-repository snapshot. Tested commit IDs remain unknown when the source does not provide them. The account, last success and coverage stay visible; failures retain the last successful facts. Credentials are owned by gh, never copied into UI assets or SQLite. Native token-entry/Keychain management and enterprise hosts are not supplied in this foundation.

## Experimental Codex execution

New projects start with the connector disabled. In the execution view, explicitly enable it and select an absolute native Codex executable path. The tested contract is `codex-cli 0.137.0`; a different version fails closed instead of claiming compatible execution. npm shims can depend on Node in the shell PATH and may fail when launched from Finder. Use the native executable supplied by the official installation rather than running shell initialization scripts. The connector does not install Codex or copy authentication credentials; sign in with the official CLI first.

The connection records its runtime instance and actual version. Its experimental product status is separate from the upstream API switch: initialization keeps `experimentalApi=false`. The pinned, generated protocol samples are in [tests/fixtures/codex-0.137.0](tests/fixtures/codex-0.137.0/contract.json), from the [official app-server protocol](https://learn.chatgpt.com/docs/app-server). Upgrading this contract requires regenerating and reviewing schemas, replaying faults and validating the native executable; a successful connection alone does not make the integration stable.

Start work only through an explicit user action with the displayed project, scope and source basis. Purpose, scope and Git revision are contextual records; they are neither sandbox permissions nor an implicit model prompt, and a revision does not assert that dirty files were committed. Initial input is a separate explicit action. Sessions, turns and runtime instances retain separate identities. Reading and polling never start or replay a model task. An exited instance can be retired only after its owned process is reaped, observed process births have no survivors, and the instance has created no sessions or execution/request records. Reconnection remains explicit; any older unresolved work stays unknown and blocks new effects. A runtime that created work is not declared safe merely because its stdio closed. Continue, input, interruption and supported approval/input answers bind to the original owned target; the client does not discover or take over sessions running in other apps or CLI processes.

Operation records live separately from source caches. They retain the original target, request fingerprint and known receipt, without storing complete prompts or transcripts by default. Sending begins only after persistence succeeds. Timeout, disconnect and crash recovery preserve unknown effects; they do not offer automatic resending. A reply or interrupt acknowledgment is distinct from confirmed effect or stopped work. The session window retains bounded recent summaries. When full, only a verified terminal or clean historical summary without unresolved operations or requests can be removed; active, waiting and unknown sessions remain protected. Durable operation history is retained. Bounded observation reports gaps and capacity faults instead of silently discarding requests. The event store is checked before launching the owned process. Its state mailbox keeps at most one pending complete snapshot and one write in flight, coalescing superseded states while retaining unresolved request identities; genuine request-capacity or storage failures still disable new effects.

Disabling blocks new work while active or unknown work remains under the original instance's management. Closing the window retains this management. Full quit checks all owned instances across projects; when activity or uncertainty remains, choose background, wait for verified completion, or explicitly request stopping. An accepted stop request alone does not confirm shutdown. External work is never stopped by the App's quit path. Local process checks use captured ancestry/group and PID birth evidence, refreshed before each stop; they cover observed owned processes and are not an atomic OS supervisor or proof of remote/escaped work. Forced termination, crashes and system restart do not guarantee ongoing execution or automatically restart tasks.

## Verification

```sh
env -u RUSTC_WRAPPER cargo test --locked -p oasis7-command-center-core
env -u RUSTC_WRAPPER cargo run --locked -p oasis7-command-center-core --example export_types
env -u RUSTC_WRAPPER cargo fmt --all -- --check
npm --prefix ui test
npm --prefix ui run build
env -u RUSTC_WRAPPER cargo clippy --locked --workspace --all-targets -- -D warnings
```

The independent workspace owns a single Cargo lockfile. Do not change `CARGO_TARGET_DIR`. Generated TypeScript contracts are committed and checked against Rust. [Command Center CI](../../.github/workflows/command-center.yml) runs core regressions, frontend tests/build and native host checks/build on macOS. The normal repository checks also continue to apply.

Single-run debug loading observations are retained in [the implementation PR](https://github.com/eng-cc/oasis7/pull/4533#issuecomment-6162418199); they are not startup guarantees or production benchmarks. Actual build/environment results belong in the implementation PR.

Desktop acceptance must additionally exercise the packaged App: native folder selection; a real repository with a dirty Markdown file; two-character Chinese search; decision save, quit/reopen and cache rebuild; history after source edits; one PR linked to two goals; unavailable gh preserving local capability; close/reopen through the menu bar; keyboard focus and Chinese composition. Browser tests verify UI behavior, not VoiceOver or macOS IME quality. Runtime acceptance additionally checks explicit enable/connect/create/input, original target management after disabling, unknown receipts without replay, pending requests, and active/unknown quit coordination. `core/tests/codex_runtime.rs` owns the fake stdio fault replays; `core/examples/codex_smoke.rs` accepts an absolute native binary path and an optional `--turn` flag for an isolated, no-write model turn. The latter is opt-in and is not run by CI. Actual build/environment results belong in the implementation PR. Signing, older-system compatibility, full VoiceOver and remote/external-session control remain unproven.

Future implementation must also exercise [AC-CC-013](../../doc/engineering/command-center/command-center.prd.md#AC-CC-013) through AC-CC-015: start the day, handle an interruption, resume work, and return from auxiliary tools. Record task completion, time, extra searches/context switches/manual entry and specific obstacles. The five-minute orientation criterion starts after available sources are loaded; loading is measured separately. A document-only revision does not provide new desktop, model-output or user-task evidence.

## Local tools

The fifth view embeds private-library management through `oasis7_context::application`: choose an independent directory, create/connect, search, edit with the read revision, archive, read/restore Git history, and export/inspect/restore encrypted context snapshots. The simple editor retains unseen metadata. Save does not commit or push. Conflicts keep drafts. Ordinary indexes, cache fallback and history projections reject private roots in both directions.

`desktop:build` bundles a matching optional context CLI and fixed catalog. Install explicitly into the App's per-user version directory; the UI returns the actual absolute path and does not claim shell PATH is configured. Existing different files are preserved. Both CLI and signer expose `info --json`; unknown build values are null.

Existing compatible signer installs are observed via fixed protected paths and original caller UID. File preparation uses the original context/envelope and JobInput, then submit/inspect retains the original job. Independent verification requires the expected public key. Prepare and doctor are not worker authorization. General upgrades remain unsupported.

Apple-signing/admin-helper integration is paused at the user's request. No system registration, privileged installation, custody management or production changes occur through this increment. See [local tools contract](../../doc/engineering/command-center/local-tools.design.md) for the held scope and actual acceptance gaps.

For explicit private development inputs, choose a source in an owned session, preview the revision and send manually. The host commits private references before sending; later rounds and restored threads remain private. Dedicated runtime requests retain approval details, while `Runtime::public_snapshot` excludes private threads. The optional connector remains disabled by default.
