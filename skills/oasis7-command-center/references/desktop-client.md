# 客户端形态与首版范围

本分册是 `oasis7-command-center` Skill 的按需实施参考，供构建客户端或确定交付范围时读取。它描述待实现的产品形态，不代表客户端、依赖或数据适配器已经存在。

本分册约定客户端的产品行为和可用性要求。开发、评审及交付继续遵循仓库现行开发流程；文档补充本身不要求实现客户端。

## 交付形态

- macOS 优先，日常正式交付为独立桌面 App，有固定入口，可直接选择并打开本地 oasis7 项目。
- Web UI 用作开发预览，便于调试页面和数据适配；日常使用通过桌面 App 进入。
- App 负责启动和管理自身本地后端，用户无需先开终端、手工启动服务或部署自有云端。
- 首版围绕个人开发中的项目掌控需求实现，展示目标、规范、执行与待决策事项。
- 个人云端机器按需作为单独执行环境接入，不设为本地看板可用的前提。

实现前检查当前仓库是否已有合适宿主、组件或数据接口。现有实现能够承载需求时优先复用，并说明采用的入口及适配范围。

## 推荐技术方案

本次调研选定的推荐基线为 **Tauri 2 + Rust 核心 + SolidJS/TypeScript 界面**：桌面外壳提供应用入口，Rust 核心读取来源并管理状态与操作，Web 前端负责四个视图及交互。

选型理由、原生 Rust 备选和重选条件见 [技术选型决策](technology-decision.md)；组件、存储、接入与发布见 [客户端架构](client-architecture.md)。技术决定不代表依赖或客户端已经实现；落地时核实当前版本与兼容性。

- SolidJS 复用当前项目的前端工具经验；Rust 保持领域逻辑与数据接入的所有权。
- 本地后端承载需要本机权限或身份的读取与操作；前端使用范围明确的接口。
- 首版 Rust 后端直接运行在 App 内，通过 Tauri IPC 连接界面，无需独立 HTTP 服务或自有 daemon。
- 由 App 管理看板自身的读取服务和连接；关闭窗口、退出应用与托管执行服务的关系按下文的生命周期约定实现。
- 不为指挥看板改造世界运行时，也不重写玩家 Viewer。游戏内 Agent 与开发会话保持不同身份。

## 首版应当可用的四个视图

| 视图 | 打开项目后应能得到的结果 |
| --- | --- |
| 目标与进度 | 当前阶段、近期交付、长期方向、里程碑依赖、已验证结果及阻塞；能打开对应条款和 PR |
| 规范与决策 | 当前适用规则、作用范围、决定理由、来源版本、待定问题及替代关系；支持搜索和查看原文 |
| 开发执行 | 当前工作与 PR、分支及工作树、适用 CI、最近活动和已接入开发会话；展示各自状态和可观察范围 |
| 待我决策 | 具体问题、必要背景、可选方案及影响、建议理由、受影响工作与处理入口 |

目标与进度按实际验收依据呈现，不用提交数或关闭 Issue 的比例代替项目完成率。只有 PR 的工作也能进入视图。

规范说明、代码合入、环境验收和开发会话运行状态分别保留；一个来源的状态变化不能自动改写其他事实。

四视图先贯通文档与 GitHub 的真实来源。开发会话尚未接入时明确显示未连接，仍可使用其他区域。

## 数据接入顺序

1. 接入选定本地仓库：识别实际 Git 根目录、分支与工作树，读取当前项目入口及有关规范。
2. 接入 GitHub：读取所选仓库的 PR、CI 与评审，按需关联 Issue/Project，并处理分页与读取失败。
3. 接入实际支持的本地开发会话：优先使用受支持接口，或本看板明确启动及管理的会话。
4. 用户需要跨机器工作时，再接入个人云端机器；为它保留独立环境身份、连接状态和能力范围。

本地与云端工作可在同一界面关联到项目目标，但不能因为分支名称相同就合并会话。未连接的环境显示其缺失范围，不冒充完整的项目执行现场。

接入失败只影响依赖该来源的区域；不要求先补齐全部接口、任务字段或开发环境才能使用看板。

## 会话能力与执行边界

每个连接分别说明以下能力，不能由其中一项推断另外两项：

| 能力 | 界面可以承诺什么 |
| --- | --- |
| 可读取 | 获取已保存历史或查询得到的状态，并展示读取时间与覆盖范围 |
| 可订阅 | 持续接收该连接范围内实际支持的事件，断线时标明状态可能过期 |
| 可控制 | 对明确会话执行实际支持的操作，并根据服务回读结果更新界面 |

优先接入自己启动或有受支持接口的会话。安装客户端不等于自动接管全机 Codex App、CLI、IDE 和云端任务；另开服务也不保证观察其他进程的全部实时状态。

接口选择、身份、状态解释和操作保护统一遵循 [Codex 接入边界](codex-integration.md)。本分册不另写一套协议字段或事件映射。

刷新状态只读取或订阅已授权范围内的信息，不启动新的模型任务。操作按钮按真实能力提供；查询或控制不可用时说明原因，不能伪造成功。

客户端管理自身服务，与管理开发任务是两个范围：

- 关闭窗口或退出客户端不构成停止既有开发任务的指令；断开看板连接与读取不能擅自终止外部任务。
- 关闭主窗口后 App 留在菜单栏，自管任务继续。完整退出时，若仍有活跃或无法确认状态的自管工作，明确提供留在后台、等待结束后退出、停止后退出；不默认停止。
- 完整退出、崩溃或系统重启后，不保证自管 stdio 任务继续；重新打开时核对来源与未决操作，不自动重跑。详细行为见 [客户端架构](client-architecture.md#八窗口退出与远端生命周期)。
- 不承诺全部后台服务退出后模型任务仍能继续。需要结束正在执行的任务时，使用明确的停止操作及对应服务确认。

## 事实、缓存与个人偏好

目标与规范沿用当前权威文档；代码交付沿用 Git、PR、CI 和评审；会话状态沿用实际接入来源。客户端生成关联与视图，不另建任务或规则权威。

- 缓存与界面偏好本地保存。缓存保留最近成功读取的数据、时间及覆盖范围，可由原始来源重建。
- 每项重要结论能追溯到来源、源版本或提交（可获得时）及观测时间；模型归纳与未知信息明确标识。
- 凭据由本地后端或适用的系统凭据机制使用，不放入前端资源、项目仓库或日志。
- 首版不扩展为通用多租户管理平台，也不要求部署中心服务才能保存布局或读取本地项目。

具体展示、进度解释与缺失状态继续遵循 [视图与数据约定](view-model.md)。

## 客户端自身的可用性验收

实现客户端时，按实际改动验证以下相关情形：

1. 启动 App、打开项目即可进入四视图；无需另开终端启动后端，缺少可选连接不阻塞已可用区域。
2. 重要内容显示来源与新鲜度，能打开原文、PR 或验证结果；历史快照与当前结果可辨认。
3. 离线、权限不足、部分分页或未接入时保留可用事实，不把缺失伪装成“没有任务”或“全部完成”。
4. 刷新页面与恢复连接不创建模型任务；可读取的会话不会因此被自动升级为可控制。
5. 关闭窗口或退出客户端不擅自停止外部开发任务；托管执行服务的退出行为与界面说明一致。
