# Codex 接入边界

仅在连接开发会话或实现执行动作时读取。以下是适配原则；实现时核对已安装 Codex 版本、官方文档、实际工具与连接范围，不把某一版本的字段写成永远可用的协议。

## 先确认可观察范围

- 区分本机 CLI、IDE、App、远端开发环境和由本看板启动的会话。分别显示环境与接入状态，不假设共享全部历史、权限或实时事件。
- 优先复用已运行的受支持服务或现有连接。确需为读取启动本地 app-server 时说明用途；不要因此启动新的模型任务。不要为查看状态调用新的 GPT Work、Codex SDK 执行或外部推理。
- 没有可用接口时，仍完成文档与 GitHub 视图。允许显示明确标注来源的人工/Agent 汇报，并保留时间和陈旧提示；不称为自动监控。

## 历史与实时状态

- 官方 app-server 的 `thread/list` 用于会话历史列表；`thread/read` 可以读取存储内容而不恢复执行或订阅。按实际接口支持的来源和仓库范围过滤，并处理分页及 worktree 路径。
- `thread/loaded/list`、运行状态及状态变化事件仅解释对应 server 的加载范围。另开一个 server 不证明能观察其他 App 进程中的所有实时会话。
- 部分子线程过滤属于实验能力，先验证版本支持。不可用时展示不完整的范围，不伪造完整 Agent 树。
- 需要运行事件时，可使用实际支持的生命周期 hooks。对适合后台记录的事件使用异步处理，保持记录轻量；不引入“未汇报不能结束”的规则。遵守宿主已有 hook 信任机制，不提供绕过参数。
- hooks 可能并发、乱序或丢失；依来源事件身份去重并回读当前状态，不能只按到达先后覆盖。状态不可核实时标为过期或未知，不猜测进程仍活跃。

## 身份与状态解释

使用“接入来源/环境 + thread 或 session ID”区分会话；子 Agent 再保留其 agent ID 和父关系。部分子 Agent 事件使用父会话的 session ID，不能只靠该字段去重。分支和项目路径只是关联信息，不是会话主键。

保持三种状态独立：

| 状态 | 回答的问题 |
| --- | --- |
| 运行状态 | 会话正在执行、等待、空闲、中断还是不可观察？ |
| 工作交付 | 修改、PR、CI、评审和合入到了哪里？ |
| 目标达成 | 所要求的验收、部署或跨任务义务是否完成？ |

`Stop` 或子 Agent 结束只说明相应轮次/执行结束；它们不能自动证明 GitHub 任务完成、CI 通过或 PR 合入。退出、断线、心跳过期也不能互相等同。

只处理必要的状态与摘要；日志或原始 transcript 可能包含凭据、提示词和其他项目内容。官方 transcript 格式不是稳定接口，不把扫描私有数据库或解析私有 JSONL 作为默认长期集成方式。

## 执行动作

仅为实际可控制的目标提供有效按钮。开始任务应有用户明确的目标和工作范围；继续与停止绑定正确环境和会话。操作结果以对应服务回读为准，结果不确定先协调已存在的运行，避免重复启动。

已有授权覆盖的继续工作按授权推进；扩大目标、改变外部影响或操作对象时才澄清新增部分。看板“推荐下一步”本身不赋予执行权限，也不代替项目合入、部署及清理规则。
