# 视图与数据约定

这些是看板内部的解释和呈现约定，不是任务管理状态机或开发准入字段。按功能实际需要实现，不要求每个 Issue、PR 或文档补齐一张新表。

## 数据来源与边界

| 内容 | 主要来源 | 不能代替它的内容 |
| --- | --- | --- |
| 目标与验收定义 | 当前 core、产品及专业条款；已确认的用户目标 | 历史路线图、模型生成的愿景和日期 |
| 规范效力 | 主责条款、文档身份、显式后继或决策关系 | 最近修改时间、出现次数、聊天中的模型猜测 |
| 代码交付 | GitHub PR 的实际 merge 状态及适用验收 | Issue 关闭、Agent 自报完成、清理 worktree 成功 |
| 验证结果 | 对应版本的实际 CI、测试和评审 | 测试源码存在、文档 active、旧截图或失败的查询 |
| 开发运行状态 | 已接入的 Codex 事件或当前会话接口 | 游戏 Agent、另一 server 的内存状态、陈旧汇报 |
| 待人处理的问题 | 明确的阻塞、用户决定需求、真实权限或输入缺口 | 把所有待办事项都标成等待用户批准 |

每项关键结论保留来源位置、源版本/提交（可获得时）、观测时间及性质：源事实、Agent 汇报、模型归纳或待核实关联。接口不提供的信息显示未知，不编造时间或版本。

缓存保留最近成功读取的数据和时间。读取失败显示错误或离线；部分分页显示“已读取范围”，不能把缺页当作全量、把 403/超时当成空列表。可重建缓存无需进入 Git；布局与筛选可保存在界面偏好中。

## 方向与进度

- 首页先显示当前阶段与近期交付，再提供长期方向与产品四域视角。工程任务可归到对应结果或单独的工程支撑筛选，不改产品分类。
- 以“长期目标 → 当前里程碑 → 关联工作 → 验收依据”提供下钻。同一个 PR 可服务多个目标，只展示关联，不复制任务。
- 复用既有稳定条款 ID、Issue URL、PR URL 和会话 ID；无 Issue 的 PR 直接作为工作项。关联不明确时标为建议关联，不能自动宣称依赖或完成。
- 展示明确的完成条件及已核实/未核实部分。只有验收集合清楚、适用范围一致且确有结果时才计算“已验证项 / 适用项”；缺失不能算通过，未覆盖不能直接当失败，未知分母不显示百分比。
- 不用 commit 数、Agent 活动数、关闭 Issue 比例或文档数量代表总体进度。一个 PR 合入只证明该交付事实；用户要求的部署、整体集成或真人验收分别呈现。
- 依赖边来自规范或已确认关系；模型推断边标为建议。保持可并行工作可见，不将完整长期愿景自动变成近期阻塞。

## 规范与决策

默认展示规则摘要、适用范围、主责来源和当前效力；按需展开理由、原文与历史替代关系。将工程流程、产品承诺、技术合同、公开状态按各自职责索引，不排出一个覆盖所有事项的总优先级。

保留原有文档状态，必要时附加面向读者的说明：

- 当前适用：有明确主责来源且在该范围生效。
- 待定/草案：仍在讨论或尚未确认，不伪造批准。
- 历史/已替代：可追溯到原决定与现行后继。
- 冲突/未核实：明确列出冲突来源与受影响结论，不能静默选一份。

“文档 active”“用户已经决定”“正式条款已更新”“实现已符合”是不同事实。世界规则旧稿中的明文约束保留其原始身份；已迁移的当前条款优先从正式入口找到，无法确认继承关系时不要自动迁入。

用户要求新增或改变决定时，记录其明确内容、理由、范围和对现有条款的关系；接受新决定不等于所有实现已经同步。只在能核实变更内容时列出“自上次查看发生的变化”，不要伪造用户已读/未读记录。

## 执行与待我处理

执行行优先显示工作目的、所服务的目标、最近实际活动、当前结果、阻塞和下一步。将 PR 状态、CI 状态与会话状态并排呈现，保留它们各自的原始状态。

一个待处理条目至少回答：具体要决定什么、为什么现在需要决定、选项和影响、推荐理由、会阻塞哪些工作。只记录必要信息；已授权的普通实现、测试、修复不反复进入审批队列。

通过面板执行动作时先展示明确目标。继续/追加指令绑定真实会话，停止指向实际运行任务；PR、部署和管理动作沿用当前项目操作边界。请求未被后端确认时显示待确认，不乐观标成完成；重试前查已有结果。

## UI 与运行方式

- 采用能快速扫读的表格、列表、依赖视图和详情抽屉；规则可搜索，目标/PR/来源可交叉跳转。避免把所有内容放成同权重的大卡片。
- 每个数据区域都有加载、空数据、错误、过期及未接入状态；颜色同时配文字，不仅靠红绿区分。
- 静态 HTML 是按生成时间成立的快照。需要自动更新时由应用负责读取/订阅，不能把“安装了 Skill”宣传为实时刷新。
- 本地后端承载需要身份的读取；凭据不进入前端 bundle、仓库、公共静态页面或日志。远程/共享部署仅在用户明确要求的目标内实施。
- 保留正常工作的区域。GitHub 失联影响实时交付视图，不能阻止查看已加载规范；Agent 未接入不阻止文档与 PR 看板使用。

## 有意义的验收情形

按本次改动选择相关情形，不新增通用门禁：

1. PR 没有关联 Issue，仍可展示其目的、merge 与 CI 状态。
2. 产品文档 active，但没有运行证据：显示当前规范，能力验收未知。
3. 文档内旧流程要求与 source-of-truth 不一致：按主责解释并标出冲突，不新建 .pm 记录。
4. PR 已合入，用户要求的部署未完成：代码交付与整体目标分别显示。
5. 接口失败、分页未完或结果过期：保留已知事实并显示覆盖限制。
6. 同分支两个开发会话：各自保留身份、活动和关联工作。
7. Agent 一轮结束，必要 CI 仍缺失/失败：只改变运行展示，不自动关闭工作。
8. 已替代规范仍被历史任务引用：能查看当时依据，也能找到当前条款。
