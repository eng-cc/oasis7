# Source Map

Use this file only when adapting `game-visual-design`, explaining a visual rubric item, or deciding whether a new visual reference belongs in the skill.

## Primary Inputs

- NN/g, "5 Principles of Visual Design in UX"
  - URL: https://www.nngroup.com/articles/principles-visual-design/
  - Borrow for: scale, hierarchy, balance, contrast, and Gestalt grouping as screenshot-review prompts.
  - Do not borrow as: generic web aesthetics detached from oasis7 gameplay state.

- Apple Human Interface Guidelines, "Designing for games"
  - URL: https://developer.apple.com/design/human-interface-guidelines/designing-for-games
  - Borrow for: screen-space, legibility, aspect-ratio, and game presentation prompts.
  - Do not borrow as: Apple-only platform rules for every viewer surface.

- Game Accessibility Guidelines
  - URL: https://gameaccessibilityguidelines.com/full-list/
  - Borrow for: readability, contrast, resizing, text, and visual clutter prompts.
  - Do not borrow as: a full universal checklist for each visual task.

- Game UI Database reference workflow
  - URL: https://www.gameuidatabase.com/
  - Context article: https://80.lv/articles/game-ui-database-collecting-references-to-inspire-designers/
  - Borrow for: reference taxonomy, HUD/menu/state-screen comparison, and inspiration gathering.
  - Do not borrow as: permission to copy screenshots, assets, layouts, or another game's visual identity.

## Oasis7 Translation Rules

- Start from the player state and action priority, not from decoration.
- Convert visual references into constraints, gap notes, and screenshot criteria.
- Treat target images and visual companions as planning artifacts until real viewer/browser/native screenshots exist.
- Route gameplay meaning to `gameplay_designer`, implementation feasibility to `viewer_engineer`, and release confidence to `qa_engineer`.
