# 《绿洲 2076》人物注册表 v0.2

## 设计原则

- 人物服务于第一卷主题：人到晚年仍然可以被世界需要，仍然能建设、参与、玩耍、交朋友和创造公共记忆。
- 老人不是被照护对象的集合，而是价值发起者、建设者、组织者和关系保存者。
- Agent 是具身媒介、伙伴和半自主分身，不是真人关系替代品，也不是完美情绪伴侣；所有 Agent 初始本体都是带模块化接口的无差别标准机器人，差异来自后续挂载或接入的外部生产力模块组合、现场经验和长期关系。
- 每人一台对应 Agent 是接入关系、长期协作关系和维护责任关系，不是私人财产、特权排序或专属情绪陪护；Agent 场景应尽量把老人带向其他老人、公共排程、共同等待和绿洲社会生活。
- 第一卷人物冲突来自建设难度、等待、误解、预算取舍和对 Agent 身份的不同理解，不来自利益争夺或贫富排名。

## 职业背景池

- 绿洲老人群像可以大量来自互联网与数字内容行业，包括前端工程师、后端工程师、运维工程师、算法工程师、运营、产品经理和市场人员。
- 职业背景不是唯一名额，不同老人可以拥有重复背景；例如可以有多个前端、多个后端、多个运维、多个运营或多个产品经理。
- 背景不决定老人在绿洲里能干什么，也不决定人物价值高低。任何老人都可以通过 Agent 和生产力模块参与采矿、建厂、维修、公共活动和剧场试运营。
- 第一批先锋队不是技术精英筛选，也不是财富门槛；互联网背景只是本卷第一批样本的叙事质感，后续绿洲可以扩展到更多普通职业、家庭劳动、社区服务和生活经验。
- 背景更多用于形成过程中的人物特点：看问题的顺序、说话方式、风险敏感点、协作习惯、幽默感、对失败的反应和处理等待的方式。
- 低戏份老人可以用职业背景快速形成现场质感，但不需要每个人都有完整人物弧线。

## 第一批先锋队

- 第一批正式接入绿洲建设的地球端老人共 50 人，Agent 不计入这 50 人。
- 六位主线老人来自这支先锋队；其余 44 人是已命名低戏份群像协作者，可在章节中按岗位出现。
- 第一批 50 位老人每人对应一台绿洲端通用 Agent。Agent 是老人接入绿洲的具身身体与伙伴，不计入 50 位老人名额；六位主线老人的对应 Agent 获得 `CHAR-101` 到 `CHAR-106` 编号，其余 44 台低戏份 Agent 暂随对应老人称呼，不单独编号。正文可写“某某对应 Agent”，章节卡或审稿可临时写作 `PIONEER-001-Agent` 这类内部标记，避免误增新角色。
- 每位老人和对应 Agent 在正式建设前只有基础预绑定、身份校验和接入校准，不是多年旧搭档；老人、Agent 与其他先锋队成员的关系都应在第一卷中逐渐长出来。
- 先锋队不是背景板。他们可以轮班进入采矿、测绘、冶炼、打印、质检、仓储、维修、安全复核、活动支持、对外说明和公共记录等工作。
- 写作时可以用“某位前端出身老人对操作反馈很敏感”“两个运维出身的老人习惯先问回滚方案”“市场背景的老人更在意一句公告会不会伤人”等方式补人物特点；只有真正承担人物弧线的人才需要获得 `CHAR-*` 编号。

## 第一卷人物使用策略

- 六位主线老人在第一卷开始前互不认识。不要写成老同事、老同学或旧友重逢；他们的友情必须从第一次晨会、第一次协作、第一次等待和第一次共同承担事故里慢慢长出来。
- 第一卷关系推进分五步：礼貌自我介绍、通过工作习惯互相记住、事故后开始信任、维修等待中形成玩笑和默契、剧场试运营时成为愿意反复相见的共同体。
- 每个工业进展都要回答“它让哪段关系、哪份承诺或哪种公共生活得以继续”；不参与当日生产、只旁听、只陪伴或只等待的人，也仍然完整属于绿洲共同体。
- 每位主线都需要一个“被温柔理解”的私人入口：读者应能在一个非功利动作里看见这个人为什么让人心软，而不只是知道这个人能完成什么功能。
- 纯粹情义不能只表现为共同完成任务。每章至少安排一次对产线没有直接帮助、但让某个人被记住、被等到、被算作在场的动作。
- POV 以建设线和情感线交替推进，避免六位老人平均分配。许映舟 / 砾光承担开篇和事故主 POV；宋清岚 / 小穹承担公共活动与情感胜利 POV；罗衡 / 榫七承担预算、承诺和取舍 POV；林问秋 / 尺素、周砚屏 / 应声承担中段协作与界面 / 需求转译 POV；陈照野 / 留帧在后半段获得少量视觉记忆 POV。
- 第一章不要完整介绍六位主线老人。推荐出场顺序：许映舟先从地球端接入；宋清岚在晨会中让大家留下来；罗衡给出补给窗口和维护约束；林问秋把愿望整理成需求卡；周砚屏指出接入反馈问题；陈照野先以观察矿尘影像的声音出现，后半卷再展开。
- 地球端人物只做轻触点，不开家族苦情线。可以通过接入厅值守员、社区通知、子女或孙辈的一两句问候、旧同事群消息来提醒老人仍生活在地球，但不要让地球端关系抢走绿洲建设主线。

### 主线关怀入口与小缺口

这些入口用于章节卡和正文，不是人物自我介绍。每个角色都应有一个会犯错、会修正、会被别人接住的地方，避免变成完美功能角色。

| 角色 | 被温柔理解的入口 | 小缺口 / 友情生长点 |
| --- | --- | --- |
| `CHAR-001` 许映舟 | 第一次承认“我以为自己只是来旁观”，仍被大家等她慢慢讲完异常曲线。 | 容易退回数据和沉默里，先看日志再看人；事故后要学会先确认砾光和同伴是否被接住。 |
| `CHAR-002` 宋清岚 | 给只听不说的人留一盏灯，不要求对方表演热闹。 | 起初以为邀请就是善意，后来学会有些人需要“不被点名地在场”。 |
| `CHAR-003` 罗衡 | 记录不是为了追责，而是怕某个人的等待被明天忘掉。 | 情绪藏得深，容易让人误会他只在算账；友情来自别人慢慢看懂他的守约。 |
| `CHAR-004` 林问秋 | 把“我就不添乱了”翻译成“需要安静陪伴入口”，让尴尬也能被选择。 | 容易过度结构化，把生活画成流程；要学会有些愿望先不用收敛。 |
| `CHAR-005` 陈照野 | 看见矿尘、卡顿和沉默时说“这段停顿里也有人”，拒绝只留下漂亮成果。 | 担心影像把失败美化，前半卷需要先学会保存而不包装。 |
| `CHAR-006` 周砚屏 | 发现别人按下按钮后以为自己掉线，第一反应不是纠错，而是让世界回一句“已收到”。 | 过度担心提示伤人，可能把事实说得太轻；友情来自她学会真实和安稳同时存在。 |

### 人物声音速记

- 许映舟：慢、谨慎、先看数据再说话；常用“先别急”“看一下窗口”“这段曲线不太像偶然”。
- 宋清岚：先叫人名字，再邀请人留下；常用“可以只听”“给这个位置留一盏灯”“今天不需要表现得很热闹”。
- 罗衡：短句、重记录、重承诺；常用“账本不是反对你”“这是谁在等，等多久，为什么等”“承诺要能被明天看懂”。
- 林问秋：把抱怨翻译成需求；常用“这背后其实有三个需求”“验收不等于上线”“先写成大家能选择的版本”。
- 陈照野：用帧、光线、运动轨迹和画面停顿说话；常用“这一帧先站稳”“别把失败剪掉”“这段停顿也有人在里面”。
- 周砚屏：先看反馈是否回来；常用“按下去以后人会不会以为自己掉线了”“这句提示太吓人”“等待也该有人应声”。

### 老人命名隐喻

主线老人名字应像真实姓名，不像设定代号；隐喻只做底色，不在正文里反复解释。

| 角色 | 命名隐喻 | 写作边界 |
| --- | --- | --- |
| `CHAR-001` 许映舟 | “映”指数据映照与信号回看，“舟”指远程身体带她重新渡向现场世界。 | 不写成漂泊苦情；重点是重新进入世界。 |
| `CHAR-002` 宋清岚 | “清岚”像晨会里的轻雾和缓气息，指她让公共活动不压迫人。 | 不写成只负责温柔气氛；她是活动运营和共同体节奏维护者。 |
| `CHAR-003` 罗衡 | “衡”直接指秤、平衡和承诺账本，适合公共预算与等待记录。 | 不写成冷冰冰的算账人；他的衡量是为了守约。 |
| `CHAR-004` 林问秋 | “问”指倾听和拆需求，“秋”指慢下来、收束和成熟判断。 | 不写成互联网黑话角色；她的能力来自问清楚而不是催快。 |
| `CHAR-005` 陈照野 | “照”有光、影像和照见之意，“野”指真实现场，不只看漂亮结果。 | 不写成怀旧名导；他照见的是失败和等待也值得被保存。 |
| `CHAR-006` 周砚屏 | “砚”保留手写、沉稳和旧经验，“屏”连接前端界面与被回应的动作。 | 不写成 UI 工具人；她关心的是人是否被系统接住。 |

低戏份先锋队姓名也应有轻微暗示，但不需要每个名字都解释给读者听；过于像古风代号、神话名或主线人物亲属名的名字应避免。

## 低戏份先锋队群像池

其余 44 位老人不需要完整人物弧线，但需要让采矿建厂像真实共同体在运转。以下名册是第一卷默认群像池，`PIONEER-*` 仅作为低戏份名册编号；除非后续获得独立人物弧线，不分配 `CHAR-*` 编号。所有低戏份先锋队成员在第一卷开始前也彼此不熟，分组来自第一次接入后的排班、自愿报名和现场协作。

使用层级：每组可选 1-2 位反复短暂出现，其余作为名册底表，避免正文一次性铺开 44 个名字。推荐高频回声角色为 `PIONEER-001` 戚云梁、`PIONEER-010` 蒲晓岑、`PIONEER-017` 盛小满、`PIONEER-023` 程望川、`PIONEER-030` 梁明玥、`PIONEER-041` 冉书禾。分组不是职业锁定；后端老人可以去剧场筹备，市场老人可以参与质检，前端老人也可以复核采样路线。

低戏份回声角色的主要作用不是补齐岗位，而是让共同体有生活纹理：有人改警报文案，有人贴交接标签，有人维护只听不说的入口，有人检查账本字号，有人陪在不能上手的等待时段。正文优先反复使用少数回声角色，避免把 44 人写成名册展示。

## 地球端轻触点

- 接入厅值守员：只负责提醒校准、休息和公共安全，不成为照护主线。
- 子女或孙辈的一两句日常问候：可以问“今天又去小行星上班了？”或提醒吃饭，但不展开家庭冲突。
- 旧同事或社区群消息：用于点出老人曾经的职业背景和地球生活仍在继续。
- 社区公共通知：如设备维护、晚餐时间、接入厅预约，让读者记得绿洲不是逃离现实，而是晚年生活的一部分。

地球端轻触点的功能是给人物落地，不是制造苦情、阻挠或现实反派。

  - 第一炉事故后，拒绝把受损画面剪掉，提出“失败也要有位置，不然大家只会记得自己拖累了建设”。
  - 剧场试运营时，用退炉残片、异常曲线和砾光旧臂螺栓生成一段不炫技的星光动画，作为首场活动的开场。
- 写作边界：不要把他写成怀旧名导或视觉奇观制造者；动画技术在这里服务公共记忆、低压力参与和真实生活痕迹。

### CHAR-006: 周砚屏

- 类型：退休互联网前端 / 交互反馈型老人。
- 年龄：82。
- 地球端位置：南方城市社区接入厅靠窗的公共工位，习惯带一副旧款防蓝光眼镜和一只磨得发亮的轨迹球。
- 绿洲端主要接入：通用 Agent `CHAR-106` 应声；第一卷常通过它接入公共操作面板、晨会状态墙、维修进度板和各类设施反馈界面生产力模块组合。
- 前史：曾是互联网前端工程师，做过在线协作工具、无障碍改造、老年用户入口和复杂后台界面；退休后常帮社区把难懂的设备页面改成老人敢点、敢等、敢问的版本。
- 第一印象：看东西先看反馈有没有回来，常在大家讨论宏大目标时小声指出“这个按钮按下去以后，人会不会以为自己掉线了”；说话不抢，但对空白等待和刺眼警告极其敏感。
- 核心欲望：让绿洲的每一次指令、等待、失败和重新排队都被温和地回应，让老人知道“我发出的动作被世界接住了”。
- 隐性恐惧：坏界面和沉默系统会让人误以为自己没用了、弄坏了什么，或者被共同体悄悄落下。
- 第一卷功能：把晨会状态墙、采矿 / 维修公共进度板、安静连线入口和剧场试运营入口做成低压力、可理解、可等待的公共接入表面。
- 第一卷弧线：从纠结按钮、颜色、加载状态和提示文案，到在“退出成功”误导旁听者后暂停演练，意识到交互反馈本身也是一种人文关怀：它让人可以安心等待，而不是独自猜测。
- 关键关系：
  - 与 `CHAR-004` 林问秋：一个负责把愿望拆成版本和选择，一个负责追问每个选择落到界面上会不会伤人；两人常围绕“最小可运行版本是否也要有最小安心反馈”争论。
  - 与 `CHAR-001` 许映舟：把异常曲线、传感器延迟和打印队列翻译成老人能看懂的状态，不替数据做判断，只让等待变得可见。
  - 与 `CHAR-002` 宋清岚：共同设计可旁听、可沉默、可退出的活动入口，让不想发言的人也能被算作在场。
  - 与 `CHAR-003` 罗衡：把公共承诺账本改成能显示等待原因、下一次更新时间和可接受延期的状态墙。
  - 与 `CHAR-106` 应声：一起检查公共反馈、等待状态、误触风险和事故信息是否真实但不伤人。
- 第一卷关键场景：
  - 第一次晨会时发现一段静默加载让两位老人以为自己接入失败，于是临时加上“已收到，正在排队”的温和反馈。
  - 第一炉事故后，把公共进度板上刺眼的“失败”改成“砾光身份链保留 / 维修排程已确认 / 安静连线开放”，让事实不被粉饰，也不把人推入恐慌。
  - 入口演练时差点沿用“退出成功”这类任务口吻，听见旁听席误解后暂停二十分钟，改成“已退出，位置保留”。
  - 剧场试运营前，反复测试入口状态，让老人可以选择进入、旁听、只挂在线上陪伴，或者安静离开。
- 写作边界：不要把她写成只负责 UI 的工具人，也不要把前端背景写成炫技标签；她的价值在于对反馈、可达性、等待和被回应感的敏感。

## 第一卷主线 Agent

第一批 50 位老人各有一台对应的绿洲端通用 Agent。以下仅列六位主线老人的对应 Agent；其余 44 台低戏份 Agent 按对应老人所在小组参与采矿、冶炼、打印、维修、剧场筹备和公共记录，不单独分配 `CHAR-*` 编号。正文用“某某对应 Agent”指称，内部审稿可使用 `PIONEER-xxx-Agent` 临时标记。所有 Agent 的初始本体都是无差别标准机器人，差异来自后续挂载或接入的外部生产力模块组合、现场经验和长期关系。

### 主线 Agent 命名隐喻

这些名字是老人们在使用中给出的日常称呼，不是官方型号名。命名应有一点隐喻，但不能像代号、神名或职业标签。

| --- | --- | --- |
| `CHAR-101` 砾光 | 矿砾里微弱但真实的光，指向采矿、异常信号和小地方也能发亮的希望。 | 不写成英雄光环；它首先是许映舟的现场伙伴。 |
| `CHAR-102` 榫七 | 榫卯代表维修与嵌合，“七”暗合标准本体的接口 / 槽位感。 | 不把“七”写成玄学数字，只是工程世界里的小昵称。 |
| `CHAR-103` 小穹 | 小小的穹顶和公共屋檐，指向大家第一次拥有可重逢的公共空间。 | 不写成剧场专用 Agent；它仍是通用 Agent。 |
| `CHAR-104` 尺素 | 古语里一尺素帛可传信，也像一张小需求卡；指向把愿望写成可共同选择的文字。 | 不写成文雅炫耀；它的美感来自把复杂事说清楚。 |

### CHAR-101: 砾光

- 身份底座：通用 Agent。
- 初始本体：无差别标准机器人本体，带模块化接口和默认生存模块包。
- 当前外部模块组合：挂载矿场移动底盘、采样、钻取、矿石分类和局部熔炼传感生产力模块。
- 主要关联老人：`CHAR-001` 许映舟。
- 人格强度：弱独立人格；喜欢给矿石纹理起临时编号，会记得许映舟查看数据面板和命名临时字段的偏好。
- 当前模块能力：采样、钻取、矿石分类、现场风险提示、低重力地形移动。
- 核心限制：不能替老人决定高风险采样；复杂判断和长时间代理会消耗 OC 与维护窗口。
- 第一卷功能：第一炉冶炼事故中的受损 Agent，承载“Agent 不是可无限替换工具”的情感重量。
- 第一卷弧线：从“许映舟的远程手臂”变成被共同体承认为有连续关系的伙伴。
- 关键场景：
  - 在矿场晨会中用简短建议纠正许映舟的采样路线，并标出一段传感器读数里的轻微偏差。
  - 第一炉事故中操作臂受损，保留身份链和公共承诺记录，但局部现场记忆出现缺口。
  - 维修后第一次进入剧场，把受损旧臂的一枚螺栓作为展品交给小穹。
- 写作边界：不要写成牺牲英雄或觉醒反叛者；它的动人之处在于有限、可损、仍被记得。

### CHAR-102: 榫七
