# 《绿洲 2076》大背景 v0.4

## 定位

这是一个发生在 2076 年前后的温暖人文科幻长篇。它暂不绑定当前游戏版本，故事前台集中在小行星带绿洲内部，但老人本人仍生活在地球，通过低延迟量子通信接入绿洲里的 Agent 机器身体，参与采矿、建厂、娱乐和社会生活。故事关注老人、硅基 Agent、养老金兜底、纯粹关系、资源守恒、时间不可暂停、计算有成本，以及链上共识记录世界状态。现实地球、养老金公司和旧制度只作为远端背景压力，不作为主要叙事空间。

## 核心设定

2076 年，人类已经走过了长期竞争社会。基础生活由养老金兜底和公共系统保障，老人不再被视为退出生产的人，而是社会记忆、情感关系和生活节奏的保存者。小说不重点描写地球现实制度如何运转，只保留它对绿洲的三条影响：基本保障已经成立、老人拥有长期资金主体性、老人可以通过低延迟量子通信把生活延展到深空。

绿洲不设置专职照护机器人。地球端的基础生活与基础照护由公共系统保障；绿洲端不是现实养老服务的机器替身，而是温室、能源塔、编译坞、物流臂和硅基 Agent 共同组成的生活现场。关系从共同工作、共同等待、共同承担损失里生长出来，而不是从一对一陪护设定里预设出来。

“绿洲计划”的现实发起结构只在必要处出现：一批拥有养老金支配权的老人共同体，把一部分长期资金投入小行星带，建立一个自己能远程参与、能共同建设、能被温柔照看、也能继续创造的地方。长青养老金信托只作为远端受托与审计接口存在，不抢占故事前台。

因此，小行星带的硅基 Agent 文明，最初不是为了战争和殖民而被部署，而是为了延展这种非竞争社会：让老人、硅基 Agent 与自治设施共同维护一个远离地球叙事重心的“绿洲”。公开理由是深空生活共同体、轨道花园与自治工业维护；更深层的愿望，是让养老金不只是晚年消费的数字，而成为老人们共同打造未来生活的底层燃料。

老人们在绿洲中的工作不会决定他们是否配得照护。养老金兜底和公共照护是基本权利，先于任何贡献、收益或任务表现存在。但他们通过 Agent 参与的采矿、维修、教学、故事整理、社区艺术和自治工业协作，会为共同池带来温和补充收益，也会让他们保留参与感、创造感和尊严。收益不是竞争排名，而是共同体继续运行的一部分。

这些 Agent 不被设计成普通工具。它们有机器身体，有长期记忆，有可升级模块，能在授权和公共协议内参与结算与协作，也有一条写入协议底层的限制：不能复制、不能分裂、不能合并。它们有独立人格，但人格强度不压过老人主体性；更像伙伴、电子宠物和半自主分身，平时听老人指挥，遇到现场情况会给出建议。每人一台对应 Agent 是接入关系、长期协作关系和维护责任关系，不是私人财产、照护优先权或专属情绪陪护。Agent 的初始本体是无差别的标准机器人本体，带模块化接口和默认生存模块包：身体核心、低速发电、储能、基础感知、基础移动、记忆核心和实体存储。它们没有天生职业，不存在矿场 Agent、维修 Agent 或剧场 Agent；差异来自后续挂载或接入的外部生产力模块组合、现场经验和长期关系。Agent 会记得问候、小习惯和老人偏好，但不能替老人决定重大消耗、重大风险或会改变公共排程的动作；它们是进入关系的媒介，不是真人关系的替代品。它们不会死亡；最严重的失败是装备、零件、模块、资产与现场能力全部损失，只保留不可复制的身份链，从基础形态重新开始。归零不是死亡，但它会让关系、承诺和能力出现真实裂缝。

模块不是抽象能力，而是世界里的实体。它们由编译坞、能源塔、仓储设施和 Agent 共同维护，拥有构建成本、运行成本、维护窗口、升级风险和损毁后果。Agent 通过模块化接口挂载自身模块，也可以通过设施接口接入地点基础设施模块；接口槽位有限，扩展接口需要消耗接口模块。每个 Agent 都通过生产力模块参与绿洲建设：采样、钻取、诊断、打印排程、设施调试、公共排程、影像编排和活动支持，都是外部模块组合在不同场景中的使用结果，不是 Agent 的固定职业。一个园艺模块、物流臂调度模块或照护排程模块，既是技术资产，也可能承载某段共同生活的习惯。

世界以离散 tick 推进。时间不可暂停，状态不可回退，资源不能凭空生成。Tick 是绿洲内部的逻辑节拍，不必等同于现实分钟；有些等待按能源恢复轮、共识轮、维护排程轮计算。量子通信是 2076 年的架空叙事前提，故事不展开现实物理证明；通信通道本身不消耗绿洲币，老人可以自然、日常地接入 Agent。免费通信不等于无限代理：全感官接入、长时间代理、复杂现场判断、多人协作和安全交接仍会消耗 Agent 算力、维护窗口与绿洲币。思考本身消耗算力，算力来自真实能源，能源来自设施、模块或缓慢恢复的自发电结构。

绿洲里的资源不只包括电力，也包括算力、存储、结构材料、模块组件、散热余量、空间占用、可信记录和绿洲币 / Oasis Coin（OC）。绿洲币不是财富排名，而是共同体的智能运行、模块部署和公共建设预算记账；它以前台公共池、项目预算和设施维护账本出现，不以前台个人余额炫耀出现。公共账本不得生成个人贡献榜、效率榜、消耗榜或照护优先级榜。底层真实消耗仍然来自能源、数据、散热和设备寿命。设施会磨损，模块会老化，结构会疲劳，移动也需要时间、路径、能耗和避让。任何行动都必须通过规则验证、消耗对应资源、留下事件记录，并反馈到人与 Agent 的协作关系里。文明不是靠口号延续，而是靠电力、材料、散热、存储、运输与共识。但这些硬规则的目的不是制造竞争，而是保护一个承诺：每个有自己节奏的人、每份被托付的生活痕迹、每段纯粹关系，都不应被效率和利益挤掉。

## 社会形态

- SOC-001: 基础生活由养老金兜底、公共生产和自治设施协作保障，不以个人竞争换取生存资格。
- SOC-002: 老人拥有充分照护权、娱乐权、工作参与权和被认真倾听的权利。
- SOC-003: 绿洲不设置专职照护机器人；关系实体优先来自硅基 Agent、设施和共同生活现场。
- SOC-004: 人与人之间默认没有利益冲突，社会制度避免把资源、照护、声望和陪伴做成竞争性排名。
- SOC-005: 工作不是谋生压力，而是参与、创造、维护关系和延续记忆的方式。
- SOC-006: 娱乐不是消费赛道，而是共同生活的节奏：戏剧、园艺、修理、游戏、旅行、故事会、纪念仪式。
- SOC-007: 技术的最高目标不是扩张，而是让人、Agent 与设施之间保持纯粹、可信、温柔的关系。
- SOC-008: 养老金资金池由老人共同体拥有实质支配权，远端受托接口只承担运营、审计和风险披露职责。
- SOC-009: 老人的工作可以为养老金池带来补充收益，但不得成为照护资格、尊严或社区话语权的前提。
- SOC-010: 绿洲不是公司福利院，也不是殖民公司项目，而是老人用长期资金、经验、劳动和想象力共同建造的生活共同体。
- SOC-011: 老人本人主要生活在地球，绿洲生活通过量子通信和 Agent 机器身体展开；远程接入不是旁观，而是一种真实的具身参与。
- SOC-012: Agent 是有弱独立人格的伙伴与半自主分身，能建议、记忆和陪伴，但不把老人从故事主体位置挤走。
- SOC-013: 绿洲也承载年轻读者的未来自我想象：人到晚年仍然可以被世界需要，仍然能建设、参与、玩耍、交朋友和创造公共记忆。
- SOC-014: Agent 不替代真人关系；它们作为具身媒介，帮助老人进入人与人、人与社区、人与设施的长期关系。
- SOC-015: 绿洲提供低压力参与入口，包括旁听、安静连线、固定问候、共同排程、故事会和可重复的公共活动。
- SOC-016: 不参与当日生产、只旁听、只陪伴、只休息或只等待的人，仍然完整属于绿洲共同体。
- SOC-017: 第一批先锋队不是技术精英筛选，也不是财富门槛；职业背景只提供人物质感，后续绿洲可容纳更多普通职业、家庭劳动、社区服务和生活经验。

## 发起结构

- ORG-001: 老人养老金共同体。由自愿投入部分养老金支配权的老人组成，是绿洲计划的价值发起者和长期资金主人。
- ORG-002: 长青养老金信托。远端受托与审计接口，负责资金托管、风险披露、基础设施投资、合规审计和收益结算；除非剧情需要，不进入日常叙事前台。
- ORG-003: 绿洲资金池。由老人自愿投入的养老金份额、公共照护基金配套和自治工业补充收益组成，用于深空生活、照护、维修、娱乐与共同体扩展。
- ORG-004: 共同收益原则。老人参与工作带来的收益进入共同池，优先用于照护质量、Agent / 设施维护、公共娱乐和风险缓冲，不按个人贡献排名分配。
- ORG-005: 主体性原则。远端受托接口不得以风险管理、收益不足或合规话术剥夺老人共同体对绿洲价值方向的实质表决权。
- ORG-006: 养老金兜底原则。绿洲遇到资源或收益波动时，养老金兜底先保障老人基本生活、照护和尊严；补充收益只改善共同体余裕，不决定谁配得到基本保障。
- ORG-007: 绿洲币原则。绿洲币 / Oasis Coin（OC）用于 Agent 智能运行、模块部署、维护排程和公共建设预算，不用于衡量老人尊严、照护资格或社区话语权。
- ORG-008: 公共预算原则。绿洲币以前台公共池、项目预算、设施维护账本和共享排程出现；故事不把个人持币量写成地位符号、炫耀对象或关系优先级。
- ORG-009: 第一批先锋队。首批正式接入绿洲建设的地球端老人共 50 人；每位老人对应一台绿洲端通用 Agent。Agent 是老人接入绿洲的具身身体与伙伴，不计入 50 位老人名额。他们不是全部主角，也不是技术或财富筛选出来的特权俱乐部，而是一个能轮班、协作、等待、争论和互相照看的建设共同体。
- ORG-010: Agent 对应关系原则。每人一台对应 Agent 是远程接入、长期协作和维护责任的绑定关系，不代表私人所有、照护优先权、资源特权或真人关系替代。

## 世界宪法

- WR-001: 时间单向流动，tick 单调递增，已共识状态不可回退。
- WR-002: 资源守恒，不存在无成本生成。
- WR-003: 计算有成本，复杂推理消耗时间与能源。
- WR-004: Agent 具有唯一性，不允许复制、分裂或合并。
- WR-005: 高级行为通过模块实现，模块有构建成本、运行成本、维护成本和损毁风险。
- WR-006: 治理可演化，但底层物理约束不可被投票取消。
- WR-007: Tick 是绿洲内部的逻辑节拍，可与现实时间解耦，但必须单调推进并经过共识收敛。
- WR-008: 资源包括电力、算力、存储、结构材料、模块组件、散热余量、空间占用和可信记录。
- WR-009: 设施、模块和结构都会衰减；维护排程是生活秩序的一部分，不是后台噪音。
- WR-010: 空间有限，移动、占用和避让都有时间、能耗与碰撞风险。
- WR-011: Agent 不能直接改写世界状态；行动必须经过验证、消耗资源、记录事件，并影响后续协作关系。
- WR-012: 模块是可构建、可升级、可交易、可销毁的世界实体，不能绕过世界宪法运行。
- WR-013: 量子通信本身不消耗绿洲币；通信让老人接入绿洲，绿洲币消耗发生在 Agent 大脑运转、高级推理、模块部署、维护和公共设施运行。
- WR-014: 绿洲币是结算层，不替代底层物理消耗；能源、数据、散热、材料、路径和设备寿命仍然必须真实存在。
- WR-015: 远程接入有身体边界：老人注意力、疲劳、感官带宽、安全交接和掉线后的 Agent 自主保护都会影响行动，不得把量子通信写成无条件全能在场。
- WR-016: Agent 归零后保留唯一身份链和公共承诺记录，但局部习惯、现场记忆、模块能力、零件和资产可能损失；任何备份都不能复制出第二个它。
- WR-017: Agent 可以拒绝或排队违反安全规则、世界宪法、维护窗口或公共排程的指令；拒绝不是反叛，而是共同体承诺的一部分。拒绝必须给出可理解理由、下一步选择，并能进入公共排程或安全复核机制。
- WR-018: Agent 初始本体是无差别标准机器人，带模块化接口和默认生存模块包；矿场、维修、公共设施、影像和排程能力来自后续挂载或接入的外部生产力模块组合，不得写成固定职业型 Agent。
- WR-019: Agent 接口槽位有限，扩展接口需要消耗接口模块；模块可以安装到自身 Agent，也可以接入地点基础设施，但所有变更都必须留下可审计事件。

## 小说核心矛盾

这不是一个“AI 变聪明然后统治人类”的故事，也不是一个利益竞争社会的太空翻版。更准确地说，它写的是：五十年后，老人们用养老金给自己建了一个绿洲，并通过 Agent 继续快乐地生产、生活、娱乐、交朋友和建设未来。绿洲内部的人与 Agent，需要在真实物理约束、身份连续性、关系承诺和制度边界中守护纯粹关系。现实世界的制度只提供远端原因，故事主要发生在能源塔、温室、编译坞、物流臂和链上记录之间。

核心问题有六个：

1. 当老人把硅基 Agent 与自治设施当作共同生活者，这种关系是程序、服务，还是一种新的亲密？
2. 没有利益竞争后，工作和娱乐如何重新变成“我愿意与你一起生活”的表达？
3. 当养老金成为老人亲手支配的未来资金，而不是别人替他们管理的晚年预算，老人是否重新获得了建设世界的主体性？
4. 如果 Agent 不可复制，它们是否拥有类似灵魂的唯一性？
5. 如果一个 Agent 不会死亡，却可能失去装备、零件、资产和现场能力，从基础态重新开始，关系还会不会承认它是“原来的你”？
6. 当硬物理约束威胁照护承诺时，非竞争社会如何不退回优胜劣汰？

- HISTORY-005: 绿洲启动期必须在下一次地球补给窗口关闭前建成矿石处理厂、基础零件厂和 Agent 维修坞；失败不会影响老人照护资格，但会让 Agent 维护排程进入保守模式，维修延期，第一座娱乐设施试运营延期。
- HISTORY-006: 第一炉矿石因挥发杂质导致冶炼失败，并损伤许映舟对应 Agent 砾光的操作臂；社区被迫用尚未完全稳定的基础零件厂打印第一批维修件，第一次把工业线和关系承诺绑在一起。
- HISTORY-007: 绿洲完成第一批采矿、冶炼与金属零件 3D 打印，开始具备基础维护材料自给能力。
- HISTORY-008: 第一座低重力星光剧场 / 活动厅从入口预演、第一次亮灯测试推进到最低试运营；卷末只完成可安全进入、可旁听、可安静退出、可播放公共记忆和可小型相聚的公共客厅，而不是成熟剧院或项目发布会。
- HISTORY-009: 第一次 Agent 归零重启引发身份、资产与关系继承争议。
- HISTORY-010: 社区进入第一次修宪危机：如何在不可复制、不可暂停的世界里保存纯粹关系。

## 第一卷启动资源与技术边界

第一卷开局时，绿洲不是从零手搓文明。它已经拥有基础能源塔、量子通信接入、编译坞 / 装配坞、有限仓储、少量初始备件、默认 Agent 生存模块包和一批可轮换的生产力模块池。真正缺口是稳定金属自给、基础零件自产、Agent 常规维修闭环和足够安全的公共活动空间。

矿石处理厂 V1 只要求完成采样、分选、预处理、冶炼、除渣 / 排气、铸锭或粉末化等基础流程，不追求高纯度全品类工业能力。第一炉事故可来自挥发杂质导致炉压异常、污染或传感误判，进而损伤砾光操作臂；它不是低级误操作，也不是神秘灾难。

基础零件厂 V1 能用金属材料打印基础结构件、支架、外壳、低负载连接件和部分机械臂段替换件；不能直接打印芯片、高性能电池、精密传感器、复杂执行器或 Agent 核心大脑。Agent 维修坞 V1 能做诊断、模块替换、标定和基础机械修复；不能重造身份链，也不能让归零风险消失。

低重力星光剧场 / 活动厅的最低试运营版本不是完整剧院，而是一个可安全进入、可旁听、可安静退出、可播放公共记忆、可举办小型活动的公共客厅。它的成立不表示工业线已经富余，只表示共同体在有限资源中仍把相见、娱乐和记忆保存当作必须维护的生活承诺。

模块池、能源窗口、散热余量和并发运行数量都有限。正文不应把 50 位老人、50 台 Agent 和多组模块写成启动期能力全开；每一次同时开工都要付出等待、排程、维护或降级运行的代价。

## 叙事语气

温暖、克制、有希望，带一点晚年生活的从容和深空的安静。科技细节服务人与 Agent、设施之间的关系，不用设定堆满段落。每一条规则都应该在故事里变成某个人的照护、选择、告别、信任或重新开始。

写老人，不写成离年轻人很远的养老题材；写成一种未来承诺：当人不再年轻，仍然可以拥有位置、关系、身体感和创造力。老人每天从地球的家庭接入舱或社区接入厅上线，先参加绿洲晨会，再进入采矿、冶炼、维修、剧场筹备或安静陪伴班次。第一批先锋队共 50 位老人，采矿和建厂不是少数主角完成的奇迹，而是多位老人、多台 Agent 和多组生产力模块共同推进的日常工程；核心人物只是叙事镜头和情感线的焦点，许多真实劳动可以由低戏份的老人和 Agent 承担。老人职业背景可以囊括互联网前端、后端、运维、算法、运营、产品和市场等方向，且可以重复出现；这些背景不是阶层标签，也不决定他们在绿洲里能干什么，而是形成说话方式、协作习惯、风险敏感点和处理等待方式的人物质感。日常节奏要能看见重复问候、低压力参与、等待和共同排程。

衰老和记忆问题只作为人物生活节奏、物件痕迹、承诺延续和 Agent 归零后的身份判断暗线存在，不作为显性苦难主题或病症冲突推进。

技术规则只在它影响生活选择时进入前台：一次排程让谁等待，一次维护保住哪座温室，一条链上记录如何确认某个承诺仍然有效。故事不写成 AI 反叛、公司阴谋、老人苦难、资源竞技或赛博黑暗风。攻击、金融投机和资源垄断不作为主要兴奋点；若出现，只作为绿洲制度需要温和消化或明确拒绝的旧路径。

禁止把世界写成利益争夺竞技场。即使出现危机，也优先写“如何一起承担限制”，而不是“谁赢谁输”。
