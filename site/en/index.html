World laws · readable boundaries

The world does not let you cheat: time, resources, and consequences have sources.

These product boundaries come from the World Rules & Core Gameplay PRD. They explain what players can influence, and why the Viewer must make evidence and unknown states explicit.

01 · persistent timeline

Time only moves forward

The same world advances along one persistent, authoritative timeline; a page refresh cannot erase its changes.

02 · resource causality

Resource changes must come from an authorized causal source/sink

Resources, facilities, and records have sources, costs, owners, and purposes; a preview or recommendation cannot mint a settled result.

03 · indirect agency

You set direction and constraints

You can influence a civilization, but you do not directly arrange every Agent action; the system must make intent, execution, and the next decision point legible.

04 · auditable consequences

Consequences remain auditable

Changes that happened should be traceable through events, replays, and receipts; unknown or degraded states stay explicit instead of being presented as success.

Source: World Rules & Core Gameplay PRD (doc/product/world-rules-core-gameplay/prd.md). This page shows controlled-scenario evidence, not live telemetry and not live world telemetry.

Download Linux Primary Package

x86_64 Debian-family Linux desktop environment, such as Debian or Ubuntu. There is no ARM or other Linux architecture package as a primary public option.

Open the `.deb` with your package installer, or run `sudo apt install ./oasis7-linux-x64.deb` on Debian/Ubuntu. For upgrades, install the newest `.deb`; do not assume changing the install directory preserves local state automatically.

Linux preview distribution includes the public `SHA256` manifest as an extra provenance check; it does not replace distro trust or local security policy.

If your distro does not support Debian packages or your device blocks installation, read the release notes for minimum guidance first. Other distro-specific behavior is outside the default support lane.

Additional Context

  • Checksum manifest: oasis7-checksums.txt
  • Linux uses `.deb` as its default primary package; operator recovery tools are shipped separately as `oasis7-linux-x64-ops-tools.tar.gz` with manifest/checksum coverage.
  • Upgrades are still manual: download the newest primary package and replace the current install yourself. There is no in-app auto-update yet.
  • Before upgrading, back up `config.toml`, `.oasis7_launcher_ux_state.json`, and `output/chain-runtime/<node_id>/reward-runtime-execution-world/` from the directory you actually launch from. Those paths are still resolved relative to the active working directory.
  • On Windows especially, do not treat “uninstall then reinstall” as state-preserving. The current uninstaller removes the install directory.
