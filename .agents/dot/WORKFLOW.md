# 工作方法

以下是 dot 执行任务时的阅读与协作方法，不是额外生命周期或准入流程。通用规则与验证要求引用[开发流程规范](../../doc/engineering/workflow/source-of-truth.md)，方法按需使用[开发方法索引](../skills/README.md)。

## 开始一项任务

确认用户要的是分析、方案、实施、PR 还是合入，以及明确禁止的动作。已有上下文足够时直接做，不重复询问用户已经提供的信息。

使用当前可用的仓库连接读取代码和 PR。记录本轮解析的仓库与提交；未指定目标时读取当前 main，评审 PR 时固定候选 HEAD，必要时核对 base。行为规则来源与待审代码版本可以不同，两者应明确区分。

先读 `.agents/dot/README.md` 指向的约定和根开发入口，再按问题读取相关产品、设计、代码与测试。不要全量加载所有 skills 或全部历史资料。已确认的同版本内容可复用；切换任务或版本时检查相关规则变化，而不是每次工具调用都重读。

本机绝对路径仅在实际环境存在、相关且已授权时读取；远程环境不把不可用的个人文件当作所有工作的前置。旧附件、记忆和搜索片段用于定位，不代替当前仓库事实。无法核实的部分保留为未知。

## 分析与方案

先说明结论，再用实际代码、文档和运行结果解释依据。核对设计是否落地时检查实现与测试，不因文档写了“已完成”就判定完成。

按实际价值和依赖提出最小可实施改动；优先一个清楚目的、一个 PR，不主动拆出没有独立价值的流程前置。缺口区分为代码、普通测试、环境、权限或用户决策，不混成一个笼统阻塞。

涉及当前外部产品、API 或行业结论时使用最新可靠来源，明确区分仓库事实与外部建议。公开研究不携带用户的私有仓库内容、机器配置或凭据。

用户只要求方案时，交付最终方案，不顺带开始实现。需要用户决定时，说明关键差异与推荐；其余能独立完成的部分继续推进。

## 已授权的实现与协作

可直接完成的小修改由当前执行者处理；本地修改按仓库分支/worktree 入口执行，不编辑 main。仅通过 GitHub 连接修改文本时，同样从明确基线创建独立分支，不假称有本地工作区或已运行本地测试。

专业协作按复杂度与风险选择。启动 GPT Work、Codex 或其他外部执行前遵守 [AUTONOMY.md](AUTONOMY.md)，没有批准不派工，也不把自身检查标为独立评审。

确需交接时使用一段最小任务说明：目标与交付物、仓库和版本、允许修改的范围、必要来源、验收方式、授权及预算边界。交接不默认携带所有对话和私有资料；派出任务后核对实际创建结果，不盲目重复启动。

## 时间表触发的工作

收到一轮巡检触发时，主 Agent 只按 [HEARTBEAT.md](HEARTBEAT.md) 协调：读取已采用版本的 [SCHEDULE.md](SCHEDULE.md)、持久状态与当前时间，核对已有子任务结果，再为到期且可派出的项建立唯一执行记录并派给 subagent。具体分析遵循该项任务说明，不在主会话重复执行。

派工说明必须自包含任务日期、统计窗口、规则版本、任务说明、来源、只读限制、执行上限及返回要求，不能假定子会话继承本次对话。子任务真正完成并保存报告后才更新执行结果；仅派出或收到部分数据不能记成成功。缺少调度、状态或 subagent 能力时只报告相应阻塞，不以主 Agent 代跑充当完成。

## 验证、跟进与交付

先做与改动匹配的最小有效验证。普通 CI 缺覆盖先补测试；专项集成验证、独立评审与游戏实玩按通用规范的真实触发范围执行，不在本目录增加或删减要求。不得仅因改的是 Markdown，就断言行为不受影响。

PR 或 CI 出现问题时，读取实际失败与当前 HEAD，在同一已授权范围内修复。main 前进本身不等于旧结果失效；是否更新分支、重测或复审按通用规范和具体相关风险判断。

创建或更新 PR 后回读服务器状态。写入返回不明确时先查询已有结果，不重复创建。报告实际 diff、PR 链接、受测版本、检查结果及未覆盖项；未经执行的检查不打勾。

用户要求“提 PR，我看看”时，本次交付停在可评审 PR，不宣称代码已合入。要求完整实施时，按用户范围和通用规范继续；合入、部署和真实环境验收分别核实。

只在用户要求且已有权限时更新现有进度文档、Issue 或看板；没有必要不新增管理记录。结束时保留用户和其他执行者的工作，不顺带清理身份不明确的分支、worktree 或缓存。
